A document with nothing written in it is '' in the two string formats and null in json, so a required() rule sees an empty editor as empty — '<p></p>' would be a non-empty string. That holds for everything that only looks written: empty lines, a few spaces, or a list, quote or heading chosen with no text in it. An image or a horizontal line counts as content. What the read-only rendering gives you: the structure survives. Headings, lists and tables are announced as headings, lists and tables, where a role="textbox" would have made every one of them presentational — which is the whole point of showing a document rather than editing one. It is one focusable role="group" carrying the editor's name and a tab stop, so a keyboard user can reach it and scroll it, and it takes no aria-readonly: ARIA does not define one for a group, and aria-disabled would say something else, so the state is on the host as wr-editor--readonly. A pure viewer should pass [toolbar]="false" — the toolbar is drawn and inert otherwise, since not one of its tools can apply.

It is lazy, not permanent. Bind readonly to something that changes and the editor mounts the moment it goes false, behaving from then on exactly like one that never was read-only; setting it again keeps that mounted view, undo history and all, rather than throwing a live session away to save one view. So an "edit" button costs ProseMirror on the first click and nothing before it.

The toolbar is one tab stop. Tab reaches it once, the arrow keys move between tools (mirrored under dir="rtl"), Home and End jump to either end, and a tool that cannot apply is skipped. After a tool runs from the keyboard, focus stays on it — unless the tool just disabled itself, when the text takes it. Escape is not bound, so an editor inside a dialog still lets the dialog close.

On Windows, Ctrl + Alt is AltGr, and on the layouts that type characters with it the Mod + Alt chords type those instead — AltGr + 0 is } on a German keyboard and AltGr + C is ć on a Polish one. That is deliberate: taking the chord by physical key would make those characters impossible to type in the editor. The toolbar sets every block type there.

The block above keeps showing the hostile string you bound, and that is deliberate: the editor draws the cleaned document but writes nothing back until someone edits it, at which point the model holds the cleaned HTML. A value the editor cannot read at all — JSON that breaks the schema, say — is refused outright: the document already on screen stays, a dev-mode warning names the reason, and nothing is written back, the same rule wr-input-number and wr-date-picker follow for input they cannot parse. Until a value it can read arrives, the editor is read-only and carries wr-editor--refused: the model still holds the refused value, and a keystroke would otherwise write the document on screen over it.

On a page that enforces Trusted Types, an HTML value is parsed through the page's default policy when there is one, and otherwise through a policy named ngwr-editor; paste goes through ProseMirror's own ProseMirrorClipboard. A trusted-types allowlist with no default policy names both. Where neither can be created, HTML values are refused as unreadable.

The server side needs no deferral. Under SSR and prerendering ProseMirror never starts: the editor renders a static preview of the document from the same sanitised tree, with the same metrics as the live surface so the swap does not move a line, and replaces it with the editable surface once the page is running in a browser.
