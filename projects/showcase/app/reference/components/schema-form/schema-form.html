Every one of them is already an Angular schema function that drives the control through [formField]. Repeating them in the spec would be a second source of truth for state the form already owns — and for the bounds it is not even possible: Angular refuses a [min] or [max] binding on a field-bound control outright (NG8022). The one thing this component adds is hidden(), which Angular's own docs say a template has to honour itself; a hidden field is drawn by nobody.

That is also the escape hatch. Point [field] at a nested object field to draw one section, and write the fields that need real markup — a colour picker, a transfer list, anything with a layout of its own — by hand beside it. The two halves bind to the same form.

That is the default because a model nests for reasons a screen knows nothing about, and because a group has a presentation of its own — a heading, a fieldset, a column count that need not match its parent's — which the spec does not describe. So a group is drawn by pointing a second <wr-schema-form> at it, with whatever markup belongs around it.

Describing the children of a group and then getting none of them is never what anyone meant, and it does not look like a mistake — nothing is missing from the page, so a half-drawn form reads as a finished one. That exact shape warns in development. A group nobody described inside stays silent, because it is a model detail this screen is not rendering.
