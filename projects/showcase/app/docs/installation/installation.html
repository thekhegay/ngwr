The missing upper bound is not a promise, and the floor is not the only compatibility question. An open-ended range means your package manager will not stop you installing ngwr beside an Angular that did not exist when the release was cut — nothing more; and no TypeScript peer and no engines field are declared here at all, because the package ships pre-compiled bundles and the versions that matter are the ones your Angular names. And the semver rule — a breaking change can no longer ride a minor, because the release script refuses the bump.

One declaration in that CSS is not a --wr-*, and it is worth knowing about before you go looking for it: the token layer sets color-scheme: light on :root, and the dark block sets color-scheme: dark on the theme attribute. That is what keeps native scrollbars, <textarea> and date / colour inputs matching the theme you are painting — without it, an app running ngwr's light theme on a dark-mode machine got dark native controls on light surfaces. The consequence to know: load the stylesheet and skip provideWrTheme() and the UA canvas is pinned light, because nothing ever writes the attribute the dark block keys on.

Three entries you will not think to add, and every app wants all three. ngwr/icon — a large part of the catalog renders either a <wr-icon> or a bare inline <svg class="wr-icon__svg"> — select and cascader chevrons, table sort and expand arrows, tree twisties, accordion carets, the alert and toast status marks — and this entry is the only thing that sizes them. ngwr/density — the --wr-density-* multipliers live there and nowhere else; every reader falls back to 1, so without it geometry is correct at md and provideWrDensity() / [wrDensity] silently do nothing at all. ngwr/overlay — .wr-overlay-sheet, the mobile bottom-sheet presentation shared by dialog, select, dropdown and popover.

Then the entry point is named after itself, not after the selector. Mostly they agree, and where they do not the surprises are worth reading once: <wr-btn> is @use 'ngwr/button', <wr-tag> is ngwr/badge, <wr-option> is ngwr/select, <wr-accordion> is ngwr/collapse, <wr-form-field> is ngwr/form, <wr-sortable-list> is ngwr/sortable-list, <wr-kbd> is ngwr/keyboard, <wr-count-up> is ngwr/counter. The rule that always holds: it is the last segment of the component's docs URL, the same string as its TypeScript subpath.

And a service mounts a component no template mentions. WrDialog.open() needs @use 'ngwr/dialog', WrToast.show() needs ngwr/toast, and WrDrawerManager.open() needs ngwr/drawer — a dialog without its entry opens as unstyled content with no panel and no backdrop.

The subpath is the API; a deeper path into the package is not. @use 'ngwr/button' resolves through the sass condition in the package's exports map, and that map is what a major has to keep working. A deep path like @use 'ngwr/button/styles/index' happens to compile anyway — Angular's Sass integration resolves files inside a package directly rather than through exports — and nothing is promised about it: the file layout under an entry point is free to move in any release, and Node's own resolution would have refused it. Write the subpath.

Adding or dropping it no longer resizes ngwr's own glyphs. An inline <svg class="wr-icon__svg"> is 1em of the font it lands in, and a <button> inherits no font-size — it takes the browser's control font, 13.33px in Chromium. Four rules in the library put a bare glyph in a button of its own: the alert dismiss, the two toast actions, the password reveal and the lightbox close. Each drew that 13.33px on a page with no reset, and the surrounding text's size under this one. They inherit the size explicitly now, so all four follow the text around them either way — which on a page with no reset is a larger glyph than before, and the reason this is a fix rather than a preference: 13.33px was the browser's number, not one anyone chose. --wr-icon-size never reached them, and still does not: only a <wr-icon> host reads that hook.

ngwr/typography-utilities adds utility classes for the type tokens and nothing else. Size is .wr-text-xs to .wr-text-5xl, weight is .wr-font-thin to .wr-font-extrabold, and the family is .wr-font-base or .wr-font-mono. .wr-leading-* and .wr-tracking-* set line height and letter spacing, and .wr-text-balance, .wr-text-pretty and .wr-truncate cover wrapping. Load it with @use 'ngwr/typography-utilities', which carries the tokens every one of its classes reads, so it needs nothing beside it. It is not ngwr/typography: that entry is the stylesheet of the wrTypography component, which you @use when you render it.

Four markdown files ship, and they are not the docs. README.md, skills/ngwr/SKILL.md and its two references/ files. There is no CHANGELOG.md and no migration guide in the package: the release notes live on /docs/migration and in the GitHub releases, so an air-gapped checkout of node_modules does not carry them. The markdown twin of a docs page is a URL, not a file — append .md to any page on this site (/reference/components/select.md) and the server renders it. The MCP server hands those URLs to your agent as text and never fetches them: it reads only files inside its own installed package and makes no network requests.
