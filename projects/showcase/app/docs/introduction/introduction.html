• Signal Forms, natively. Every value control binds with [formField] — there is no ControlValueAccessor anywhere in the library.
  • Signals and zoneless. Standalone components, input() and model() throughout, and no zone.js required.
  • Only what you use. {{ quality.entryPoints }} entry points, one per component — you import and @use what you render and nothing else.
  • Yours to restyle. Every value is a CSS variable: override a token to change the whole app, or a component's own hook to change one.
  • Server-rendered. Components render under SSR and hydration — every page of these docs is prerendered.

The counters below are written by scripts/gen/quality.ts, which counts the repository during the showcase build. None of them is typed in by hand — that is the only way a page like this is still true a year after it was written.

Test cases are declared it() call sites. A parameterised form like it.each, or a call inside a loop, makes the figure a floor, and the label then reads “at least”.

“Documentation pages” counts routes that render one — the layout shell and the ** 404 are not pages, so neither is in the {{ quality.docRoutes }}.

The version is read from projects/lib/package.json and cross-checked against NGWR_VERSION; a mismatch fails the build. The single runtime dependency is {{ quality.runtimeDependencies.join(', ') }}.

Three sweeps, because no single one of them reaches the whole surface.

check:a11y

  • Runs. On every pull request: axe over the prerendered HTML, in JSDOM.
  • Sees. Accessible names, ARIA validity, roles, id references, landmark and heading structure. It fails on any serious or critical violation.
  • Cannot see. Anything that depends on computed style — JSDOM loads no stylesheets — and nothing in a hover, a focus ring or an overlay.
  • Accepted. Nothing. The baseline is empty.

check:contrast

  • Runs. Nightly, in a real Chromium with real CSS, in both themes, on every route.
  • Sees. Colour contrast and target size, the two rules the structural sweep cannot run — and placeholder text, which axe itself never measures.
  • Cannot see. Hovers, focus rings and overlays. It gates on routes per rule, so a new violation on a route that already fails passes silently.
  • Accepted. A few decided trades in scripts/baselines/contrast.json — the calendar's out-of-month days, the carousel dots, the table header's sort and filter controls — each with its reason.

check:state-a11y

  • Runs. Nightly, driving a curated table of states with the full axe rule set inside each.
  • Sees. States a user has to create: a hover, a focus ring, an open dialog, a select panel.
  • Cannot see. Whatever is not in the table — so a full run prints its own coverage, and a state that fails to paint fails the run.
  • Accepted. The same calendar days and target sizes as above, in scripts/baselines/state-a11y.json.

What no gate reports

--wr-border-base measures 1.48:1 in light and 1.41:1 in dark, under the 3:1 WCAG 1.4.11 asks of a control boundary. Both fixes were costed and the lighter hairline was kept; axe has no non-text-contrast rule, so nothing reports it.

Colour is never the only channel. Components that report a state draw a shape for it — alert and toast a glyph, timeline a silhouette — while a tag or badge colour is decoration, and the words carry the state. check:color-only holds every colour-only rule in the library to a written reason.

ngwr is built so an assistant can work with it as well as a person can — consistent patterns, documentation generated from the source, and an MCP server inside the package.

Predictable patterns

Every component has the same shape: signal inputs, model() for two-way values, BEM classes and one entry point — so generated code reads like code a person wrote.

An agent skill, llms-full.txt and an MCP server ship with the package, generated from the library source, so an assistant reads the API you installed.
