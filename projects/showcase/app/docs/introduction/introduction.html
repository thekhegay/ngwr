• Signal Forms, natively. Every value control binds with [formField] — there is no ControlValueAccessor anywhere in the library.
  • Signals and zoneless. Standalone components, input() and model() throughout, and no zone.js required.
  • Only what you use. {{ quality.entryPoints }} entry points, one per component — you import and @use what you render and nothing else.
  • Yours to restyle. Every value is a CSS variable: override a token to change the whole app, or a component's own hook to change one.
  • Server-rendered. Components render under SSR and hydration — every page of these docs is prerendered.

Every counter says what it measured. Test cases are declared it() call sites, which equals the real figure only while nothing mints cases at runtime — so a parameterised form (it.each) or a call site inside a loop makes the generator print the file and line and label this figure a floor, and the page then reads “at least”. A spec file that yields zero cases still fails the build outright, because that is not a way of writing tests, it is what a broken comment-stripper looks like. “Documentation pages” counts routes that render one: the layout shell and the ** 404 both declare a component and neither is a page, so neither is in the {{ quality.docRoutes }}. The version is read from projects/lib/package.json and cross-checked against the NGWR_VERSION constant, which is a separate copy; a mismatch fails the build rather than picking a side. The single runtime dependency is {{ quality.runtimeDependencies.join(', ') }}.

check:a11y

Every pull request. axe over the prerendered HTML, in JSDOM. The structural half: accessible names, ARIA validity, roles, references to ids that must exist, landmark and heading structure. It fails on any serious or critical violation and the baseline is empty. That class is real — the audit it was written after found an unnamed speed-dial trigger, icon-only segmented options, and a dialog promising an aria-modal it did not honour. Anything that depends on computed style. JSDOM loads no stylesheets and does no layout, so color-contrast and target-size are switched off explicitly rather than left to report noise. And prerendered HTML holds no hover, no focus ring and nothing inside an overlay. Nothing. scripts/baselines/a11y.json is {}, so there is no allowance to hide a regression in — which is exactly why the two blocks below have to state theirs.

check:contrast

Nightly. A real Chromium, real CSS, both themes, every canonical route. Exactly the two rules the structural sweep has to disable. It reports axe's own measured ratio instead of re-deriving one, emulates prefers-reduced-motion so an animation caught mid-flight cannot report a failure that describes a single frame, and pins the clock so a demo built from new Date() cannot move its own route count overnight. It also measures what axe never does: placeholder text. axe reads an empty field's typed-text colour, which is how input placeholders at 2.91:1 passed as 17.85:1, so every field showing its placeholder gets that colour copied onto its text for one scoped pass. A page at rest is all it measures, so hovers, focus rings and overlay contents stay out of reach. And it gates on route counts per rule, not on nodes — a brand-new violation on a route that already fails passes silently. Not hypothetical: deepening the dark primary broke wr-calendar__day--today at 4.06:1 on a route already baselined for something else, and the sweep printed “no new violations”. Change a token, measure the elements you changed. The entries in scripts/baselines/contrast.json, one per rule, theme and prefers-contrast mode, each allowing a number of routes rather than of nodes. The worst is wr-calendar__day--out-of-month at 2.23:1 — enabled buttons the arrow keys reach, so the exemption for inactive controls does not apply to them, and it is opacity: 0.55 rather than the colour that drops the ratio. The rest are the carousel's 8×8 pagination dots, the swatch grid on Colour tokens (which labels every shade of a ramp with a token calibrated for the base shade), disabled controls axe cannot recognise as disabled because the attribute sits on a custom element, and the table header's sort and filter controls on a fine pointer — 12×12 apiece and 6px apart, a decided trade rather than debt, because widening them for every pointer moves the caret and the funnel apart in every desktop table. Every entry carries the reason it was accepted.

check:state-a11y

Nightly. A curated table of states, driven in a browser, with the full axe rule set inside each one. The states a user has to create: a hover, a focus ring, an open dialog, a select panel, a context menu. Seven real AA failures were found there by hand, every one long-standing and every one under a green run. Colour is not all of it — the structural rules had never run inside an overlay either, which is how a role="button" span nested inside a real <button> survived in the window taskbar, on a tab that only exists while a window is minimized. Whatever is not in the table. A curated list that stopped growing looks exactly like one that covers the catalog, so a full run prints its own coverage — state-dependent classes in the built stylesheet against the classes it actually painted — and a state that failed to paint fails the run, because a clean axe result over an element that never rendered is indistinguishable from a pass. The entries in scripts/baselines/state-a11y.json, one per state and theme, come down to a few decisions rather than a pile of problems: the same out-of-month calendar days as above (2.23:1 light, 3.11:1 dark) reached through two separate states, and target-size on the window chrome's 14×14 traffic-light buttons and on the carousel dots again. Each is a design call with the alternative costed in the file — not a finding nobody looked at.

ngwr is built so an assistant can work with it as well as a person can — consistent patterns, documentation generated from the source, and an MCP server inside the package.

Predictable patterns

Every component has the same shape: signal inputs, model() for two-way values, BEM classes and one entry point — so generated code reads like code a person wrote.

Docs an agent can read

An agent skill, llms-full.txt and an MCP server ship with the package, generated from the library source, so an assistant reads the API you installed.
